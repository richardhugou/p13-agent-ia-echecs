Le problème

L'histoire et le besoin

La FFE prépare ses jeunes espoirs aux championnats d'Europe. 60 000 licenciés, ~60 % de jeunes, quelques centaines d'entraîneurs diplômés — le goulot d'étranglement, c'est l'humain.

Imaginez Léa, 12 ans : elle veut travailler ses ouvertures ce soir, son entraîneur n'est pas disponible.
La commande d'Alan : un POC en deux semaines — une IA qui l'accompagne pendant qu'elle joue.

Ce que l'IA doit savoir faire pour elle :
1. proposer les coups reconnus par la théorie   2. expliquer les idées en citant ses sources
3. recommander des vidéos adaptées   4. évaluer objectivement quand elle sort des sentiers battus

Le produit · Le parcours

Le parcours de l'élève

1. Elle dit qui elle est — « je joue les Noirs » : le plateau se retourne vers elle.

2. Elle choisit une ouverture à travailler, ou installe sa position en jouant ses coups et ceux de l'adversaire — une erreur se corrige (« Annuler le coup »).

3. Elle appuie sur « Lancer l'IA » — c'est elle qui décide quand demander conseil.

4. Elle lit : coups + statistiques, explication avec sources cliquables, vidéos — et peut poser une question libre.

5. Hors théorie, l'agent change d'outil : évaluation objective du moteur.

À aucun moment le système n'invente : il va chercher, il assemble, il cite.

L'architecture · 2/2 — Le cœur documentaire

Pourquoi une base vectorielle ?

Léa demande : « pourquoi le fou vise f7 ? » — aucun mot-clé ne relie sa question à la page « Giuoco Piano ». Il faut chercher par le sens. La base vectorielle est la mémoire documentaire de l'agent.

Les 477 fiches (FR + EN, dans le même espace de sens) sont vectorisées une fois ; chaque question l'est à la volée ; la similarité cosinus mesure l'angle entre les deux (1 = même sujet, 0 = sans rapport). La recherche se fait dans le rayon de l'ouverture jouée uniquement — hors bibliothèque : zéro fiche, réponse honnête.

Mesuré : recherche 7–11 ms · séparation sujet/hors-sujet 0,29 → 0,50 (notebook 02) · le détail (modèle, dimensions, index) : documentation technique.

La preuve · La démarche

Des décisions guidées par la mesure

1. Le choix du LLM — plan initial : API payante. Le banc de mesure (4 modèles locaux) a montré qu'un modèle de 3,2 Go répond en 3–7 s en bon français → local, 0 €. La décision a été révisée par les chiffres.

2. Le chunking — version A (fenêtres de 1 000, top-3) contre version B (fiches 300–500 avec contexte, top-5, filtre par ouverture) : même score de routage… donc l'étalon était trop facile — c'est une découverte, pas un échec ; l'étalon v2 est l'axe suivant.

3. L'abstention — une question hors corpus citait des sources voisines (mesuré). Aucun seuil ne sépare (0,618 vs 0,619 à un millième !) → règle déterministe : le corpus n'est consulté que dans le rayon de l'ouverture jouée ou nommée. Vérifié : 5/5 pièges bloqués, 0 question légitime sacrifiée.

L'histoire complète de chaque décision (données, figures, tests) : documentation technique + annexes C-D.

La perspective · Partie 2

Et si la connaissance était dans une vidéo ?

La demande d'Alan : indexer les vidéos par position, pas par titre — « cette position est expliquée à 4 min 32 ».

vidéo  →  images extraites  →  détection de l'échiquier  →  position → FEN  →  l'agent existant

Ce n'est pas un deuxième agent : la vidéo devient des positions FEN — la même clé que tout le POC. Les capacités d'analyse sont exposées en MCP : des serveurs d'outils indépendants que tout agent futur de la FFE peut appeler.

Bénéfice chiffré : ≈ 0,10–0,15 €/vidéo contre 7,50–15 € à la main (×50 à ×100). La limite dure est juridique (CGU : jamais les fichiers) → MVP : licences Creative Commons + transcripts d'abord, vision 2D ; le 3D — le seul vrai entraînement de modèle du projet — attendra les chiffres du pilote.

Build MVP 15–20 k€ · opex ~100–150 $/mois à 1 000 vidéos/mois · roadmap avec critères go/no-go chiffrés.

Livrables joints : note bénéfices/limites (9 pages) · schéma d'architecture MCP · étude de faisabilité et coûts.

D — Le choix du LLM en détail

Décision prise sur mesures (campagne de 4 modèles locaux, 22/08) — et révisée par elles : le plan initial (API) est tombé devant les chiffres du local.

OptionCoûtVerdict mesuré
qwen3.5:4b local (Ollama) ✓0 €3,2 Go de RAM · 3–7 s/réponse · FR correct avec garde-fous (faits annotés, temp 0,2)
Claude Haiku 4.5 (API)1 $ / 5 $ par M tokensoption qualité — activable par variable d'environnement
Gabarit déterministe0 €repli toujours juste : réponse exacte et sourcée même sans LLM

Réversible par conception : le LLM ne fait que la mise en forme finale (LLM_PROVIDER) — il n'est jamais la source de vérité. Un mot de théorie : un LLM prédit le mot suivant, il est fait pour être plausible, pas pour être vrai — d'où les faits annotés (« Fc5 — le Fou va en c5 »), la basse température et le repli déterministe.
