Le problème

L'histoire et le besoin

La FFE prépare ses jeunes espoirs aux championnats d'Europe. 60 000 licenciés, ~60 % de jeunes, quelques centaines d'entraîneurs diplômés — le goulot d'étranglement, c'est l'humain.

Imaginez Léa, 12 ans : elle veut travailler ses ouvertures ce soir, son entraîneur n'est pas disponible.
La commande d'Alan : un POC en deux semaines — une IA qui l'accompagne pendant qu'elle joue.

Ce que l'IA doit savoir faire pour elle :
1. proposer les coups reconnus par la théorie   2. expliquer les idées en citant ses sources
3. recommander des vidéos adaptées   4. évaluer objectivement quand elle sort des sentiers battus

Le produit · Le parcours

Le parcours de l'élève : un scénario suivi jusqu'au bout

1. Choix du camp : « je joue les Blancs » (un seul jeu de pièces, point de vue joueur).

2. Point de départ : l'Italienne (parmi 8 ouvertures du manifeste), ou position libre.

3. Réponse adverse automatique : l'agent joue le coup le plus joué par les maîtres.

4. Détection hors théorie : signalement immédiat et passage de main.

5. Demande d'analyse (« Demander à Chessbot ») : coups + stats, flèches, explication sourcée, vidéos.

6. Évaluation tactique : calcul objectif Stockfish sur coup douteux (-1,47 cp).

Les faits proviennent des outils spécialisés ; le LLM intervient uniquement pour formuler la réponse.

La base vectorielle

La base documentaire : retrouver une information par son sens

Exemple de recherche sémantique : « pourquoi le fou vise f7 ? » (aucun mot-clé exact ne relie la question à la page « Giuoco Piano »).

Les 477 fiches (FR + EN, dans le même espace vectoriel 1024d) sont indexées une fois. La recherche par similarité cosinus s'effectue dans le rayon de l'ouverture active : hors bibliothèque, zéro fiche transmise.

Performances mesurées : recherche 7–11 ms · séparation sémantique cible/hors-sujet portée de 0,29 à 0,50 (notebook 02).

B — Le protocole d'évaluation en détail

Le gold set : 25 questions étiquetées à la main, figées avant tout réglage — 15 directes (FR + EN), 5 par position (FEN), 5 pièges où la bonne réponse est de s'abstenir. Runs A vs B (MLflow) : A « naïf » (chunks 1 000, top-3, sans filtre) vs B « soigné » (300–500 + fil d'Ariane, top-5, filtre ECO) — recall@5 et MRR 1,0 partout → l'étalon v1 mesure le routage ; la vraie différence (qualité des fiches transmises) exige des labels fins.

Le cahier d'expériences MLflow réel (gold-set-rag). Mesure d'adoption des embeddings : préfixe d'instruction → séparation 0,29 → 0,50 (notebook 02).

C — La décision d'abstention, l'histoire complète

1 · Préjudice mesuré (notebook 05) : une question hors corpus faisait citer 5 fiches adjacentes en sources.

2 · Le seuil pur est impossible (notebook 07, ci-contre) : pièges grossiers ≤ 0,548, mais entrelacement 0,618–0,663 — et les vraies questions scorent bas (démo : 0,629).

3 · La règle des rayons signés : le corpus n'est consulté que dans un rayon établi par la position (ECO) ou nommé dans la question ; hors manifeste → zéro fiche + réponse honnête. Filet à 0,58. 5/5 pièges bloqués par construction, 0 légitime sacrifiée — tests garde-fous versionnés.

D — Le choix du LLM en détail

Décision prise sur mesures (campagne de 4 modèles locaux, 22/08) — et révisée par elles : le plan initial (API) est tombé devant les chiffres du local.

OptionCoûtVerdict mesuré
qwen3.5:4b local (Ollama) ✓0 €3,2 Go de RAM · 3–7 s/réponse · FR correct avec garde-fous (faits annotés, temp 0,2)
Claude Haiku 4.5 (API)1 $ / 5 $ par M tokensoption qualité — activable par variable d'environnement
Gabarit déterministe0 €repli toujours juste : réponse exacte et sourcée même sans LLM

Réversible par conception : le LLM ne fait que la mise en forme finale (LLM_PROVIDER) — il n'est jamais la source de vérité. Un mot de théorie : un LLM prédit le mot suivant, il est fait pour être plausible, pas pour être vrai — d'où les faits annotés (« Fc5 — le Fou va en c5 »), la basse température et le repli déterministe.
